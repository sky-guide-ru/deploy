# Письма сайта прямо со своего сервера

Сайт шлёт письма только владельцу: отзывы «Сообщить об ошибке», тревоги и сводку за сутки со страницы «Сервер».
Раньше они уходили через Resend с адреса `onboarding@resend.dev`. С прямой отправкой сервер сам относит письмо
на почтовый сервер получателя (для Gmail это `gmail-smtp-in.l.google.com`, порт 25) с адреса `noreply@sky-guide.ru`.
Отдельный почтовый сервер (Postfix и т. п.) не нужен: всё делает сам сайт.

Чтобы Gmail поверил, что письмо правда с `sky-guide.ru`, а не спам, нужно вот что:

| Что | Зачем |
|---|---|
| Порт 25 открыт у хостера | без него письмо не уйти |
| A-запись `mail.sky-guide.ru → 203.0.113.10` | имя, которым сервер представляется почте получателя |
| PTR `203.0.113.10 → mail.sky-guide.ru` | обратная запись: по IP видно то же имя. Без неё Gmail письмо не примет |
| SPF (TXT у `sky-guide.ru`) | список IP, которым можно слать письма от имени домена |
| DKIM (TXT у `sky._domainkey.sky-guide.ru`) | открытый ключ для проверки подписи каждого письма |
| DMARC (TXT у `_dmarc.sky-guide.ru`) | что делать с письмами, которые не прошли проверку. По желанию, но лучше добавить |

Resend остаётся запасным: если напрямую не получилось (DNS ещё не обновился, Gmail отказал), письмо уйдёт через него,
а причина будет видна в проверочном письме и в журнале сайта.

## Шаг 1. Включить прямую отправку на сервере

В `/opt/skyblock-tracker/.env` добавь строку (строки `RESEND_API_KEY` и `MAIL_TO` не трогай, это запасной путь):

```
MAIL_DOMAIN=sky-guide.ru
```

Применить: `ssh root@203.0.113.10 "cd /opt/skyblock-tracker && docker compose up -d"`.

При первом письме или проверке сайт сам создаст ключ DKIM в `data/mail/dkim-private.pem`. Этот файл никому не отдавай;
он попадает в ночные копии вместе с `data/`. Если его удалить, сайт создаст новый ключ, и запись DKIM в DNS придётся заменить.

## Шаг 2. Записи в DNS

Открой сайт → «Сервер» → блок «Почта и тревоги» → **«Проверить DNS для прямой отправки»**. Там пять строк с точными
значениями: что вписать и что сейчас в DNS. Значение DKIM длинное и есть только там: его ключ создал сервер.

Записи добавляются там, где управляешь DNS домена `sky-guide.ru` (у регистратора, например reg.ru → «Домены» →
`sky-guide.ru` → «DNS-серверы и управление зоной»). Поле «Имя» (Subdomain, Host) пишется без домена:

| Тип | Имя | Значение |
|---|---|---|
| A | `mail` | `203.0.113.10` |
| TXT | `@` | `v=spf1 ip4:203.0.113.10 ~all` |
| TXT | `sky._domainkey` | `v=DKIM1; k=rsa; p=…` — скопировать целиком из проверки на сайте |
| TXT | `_dmarc` | `v=DMARC1; p=none; adkim=s; aspf=s` |

- **SPF должна быть одна.** Если у `@` уже есть TXT, начинающаяся с `v=spf1`, не создавай вторую, а допиши в неё
  `ip4:203.0.113.10` после `v=spf1`. Проверка на сайте покажет готовую строку.
- **DKIM вставляй одной строкой**, без кавычек и переносов. Если панель режет длинные строки, она сама разобьёт значение на куски, это нормально.
- `p=none` в DMARC значит «только наблюдать». Когда письма месяц приходят нормально, можно сменить на `p=quarantine`.

## Шаг 3. PTR в панели хостера

Делается после A-записи `mail` из шага 2 (некоторые панели сверяют, что имя указывает на этот IP).

1. Панель хостера → твой сервер → вкладка **Network** (Сеть).
2. Рядом с IP `203.0.113.10` нажми значок инструментов (гаечный ключ) → **Update PTR**.
3. Впиши `mail.sky-guide.ru` (без точки в конце) и сохрани.

## Шаг 4. Проверить

1. Подожди: DNS обновляется от 5 минут до нескольких часов, PTR у хостера обычно до часа.
2. «Сервер» → «Проверить DNS для прямой отправки»: должны быть ✓ у порта 25, A, PTR, SPF и DKIM.
3. «Отправить проверочное письмо»: ответ должен быть «Письмо ушло напрямую со своего сервера».
   Если там «через Resend», рядом написано, почему не ушло напрямую.
4. В Gmail открой письмо → «⋮» → «Показать оригинал». Должно быть `SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`.

## Важно: не попасть в бан у хостера

Хостер открывает порт 25 с условием: жалобы на спам — и сервер заблокируют навсегда. Сайт шлёт письма только на почту
владельца (адрес из `MAIL_TO`), посетителям и на чужие адреса не пишет ничего. Так и должно остаться: рассылки
игрокам, письма для входа и т. п. через прямую отправку не делать, для них есть Resend.

## Как выключить

- Временно: `MAIL_TRANSPORT=resend` в `.env`, затем `docker compose up -d`. Письма снова пойдут через Resend.
- Совсем: убрать строку `MAIL_DOMAIN`.
