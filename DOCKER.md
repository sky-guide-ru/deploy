# Сайт в Docker: запуск на своём сервере

Сайт упакован в Docker. На сервере работают три контейнера:

| Контейнер | Что делает |
|---|---|
| `app` | сам сайт (Node 22). Наружу не открыт |
| `caddy` | отдаёт сайт на портах 80 и 443. Если задан домен, сам получает и продлевает SSL-сертификат |
| `updater` | раз в минуту проверяет ветку main. Есть новое — пересобирает и перезапускает сайт. Не собралось или не запустилось — возвращает прошлую версию (как `scripts/supervisor.js` на ПК) |

Данные лежат **рядом с кодом, на диске сервера**, а не внутри контейнеров, и переживают любые пересборки:

- `.env` — ключи и настройки;
- `data/` — аккаунты, история цен, рейтинг, кэш;
- `packs/` — zip-архивы ресурс-паков;
- `db/icons/` — готовые иконки.

## Какой сервер нужен

- **Ubuntu 22.04/24.04 или Debian 12**, 1–2 ГБ памяти (на 1 ГБ скрипт сам добавит подкачку), диск от 15 ГБ.
- Подойдёт любой дешёвый VPS в Германии или Нидерландах (около €4–5 в месяц). Перед оплатой проверь, что берут российские карты.
- Нужен доступ по SSH под root (логин и пароль или ключ хостер пришлёт после оплаты).

## Установка (один раз, ~15 минут)

Всё ниже делается с ПК, в PowerShell, из папки проекта. Вместо `1.2.3.4` подставь IP своего сервера.

**1. Скопировать скрипт на сервер и запустить его:**

```powershell
scp deploy\setup-vps.sh root@1.2.3.4:/root/
ssh root@1.2.3.4 "bash /root/setup-vps.sh"
```

**2. Дать серверу доступ к репозиторию.** Репозиторий приватный, поэтому на первом запуске скрипт остановится и покажет строку, которая начинается с `ssh-ed25519`. Дальше:

1. Открой https://github.com/sky-guide-ru/sky-guide/settings/keys/new
2. В поле Title напиши `VPS`, в поле Key вставь эту строку. Галочку «Allow write access» **не ставь**. Нажми Add key.
3. Запусти скрипт ещё раз той же командой `ssh root@1.2.3.4 "bash /root/setup-vps.sh"`.

Скрипт поставит Docker, включит файрвол (открыты только SSH, 80 и 443), соберёт и запустит сайт и настроит ночные копии данных. В конце он напишет адрес вида `http://1.2.3.4`: сайт уже работает, но пока без твоих данных.

**3. Перенести данные с ПК.** Сначала останови сайт на ПК: закрой окно `npm run share`. Иначе два сайта будут вести разные данные и вдвоём тратить лимит ключа Hypixel. Потом там же в PowerShell:

```powershell
tar -czf move.tgz --exclude=data/neu-repo.zip --exclude=data/icons .env data db/icons packs
scp move.tgz root@1.2.3.4:/root/
ssh root@1.2.3.4 "bash /opt/skyblock-tracker/deploy/import-data.sh /root/move.tgz"
```

После этого на сервере будут твои ключи, аккаунты, история цен, паки и иконки. Строки из `.env` с ПК про туннель (`BEHIND_CLOUDFLARE`, старый `SITE_URL`) на сервере не нужны. Если они есть, убери их в `/opt/skyblock-tracker/.env`.

**4. Включить HTTPS.**

- Без покупки домена: `ssh root@1.2.3.4 "bash /opt/skyblock-tracker/deploy/set-domain.sh sslip"`. Сайт откроется по адресу вида `https://1-2-3-4.sslip.io`.
- Свой домен или поддомен (например, от reg.ru или тот, что дал друг): у регистратора создай **A-запись** `sb.example.ru → 1.2.3.4`, подожди 5–30 минут, затем:
  `ssh root@1.2.3.4 "bash /opt/skyblock-tracker/deploy/set-domain.sh sb.example.ru"`.
  Если домен подключён через Cloudflare, выключи оранжевое облако (режим «только DNS»): через прокси Cloudflare сайт у многих в России не открывается.

Сертификат Caddy получит сам и сам будет его продлевать.

## Каждый день

Делать ничего не нужно: всё, что слито в main, само появляется на сервере примерно через 1–3 минуты (пересборка занимает дольше, чем на ПК). Историю обновлений и откатов видно на странице «Сервер» у владельца.

Полезные команды (сначала `ssh root@1.2.3.4`, потом `cd /opt/skyblock-tracker`):

| Что | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Журнал сайта | `docker compose logs app --tail 100 -f` |
| Журнал автообновления | `docker compose logs updater --tail 50` |
| Перезапустить сайт | `docker compose restart app` |
| Поменял `.env` — применить | `docker compose up -d` |
| Добавил паки в `packs/` | `docker compose restart app` |
| Выключить автообновление | `AUTO_UPDATE=0` в `.env`, затем `docker compose up -d` |
| Обновить вручную прямо сейчас | `git pull && docker compose up -d --build` |
| Сколько памяти ест | `docker stats --no-stream` |

## Резервные копии

Каждую ночь в 04:30 (по времени сервера) `deploy/backup.sh` сохраняет `data/` и `.env` в `/var/backups/skyblock` и хранит последние 14 копий. Хостеры копий обычно не делают, поэтому раз в неделю стоит забрать свежую копию себе:

```powershell
scp root@1.2.3.4:/var/backups/skyblock/latest.tgz .\backup-skyblock.tgz
```

Вернуть копию на сервер можно той же командой `import-data.sh`, указав этот архив.

## Запуск в Docker на своём ПК (по желанию)

На ПК с Docker Desktop: `docker compose up -d --build`, затем открой http://localhost. Автообновление в этом режиме выключено, потому что `COMPOSE_PROFILES` пустой. Для обычной работы на ПК по-прежнему подходит `npm run share`.

## Безопасность

Что сайт делает сам: пароли хранит только хешем, ключи Hypixel и Anthropic не уходят в браузер и в ответы API,
подбор пароля ограничен (10 попыток с адреса и 30 на ник за 15 минут), с одного адреса — не больше 600 запросов
в минуту к API (`API_PER_MIN`), 3000 картинок (`IMG_PER_MIN`), 240 аватарок (`HEADS_PER_MIN`) и 8 открытых вкладок
(`STREAMS_PER_IP`); владельца лимиты не касаются. Адрес посетителя берётся только от своего Caddy.

Что на тебе:
- **Длинный пароль владельца** (от 12 символов, нигде больше не используй) — владелец управляет аккаунтами.
- **Двухфакторный вход на GitHub.** Сервер сам ставит всё, что попало в `main`, поэтому доступ к GitHub = доступ к серверу.
  Ключ сервера на GitHub добавляй как deploy key **без** галочки «Allow write access».
- **Вход на сервер по SSH-ключу**, пароль root — длинный; `.env` никому не пересылай.
- Если поставишь Cloudflare перед сервером, все посетители будут видны с адресов Cloudflare — тогда лимиты
  надо перенастроить (напиши Claude).

## VPN на том же сервере (AmneziaVPN)

Если на сервер ставится AmneziaVPN с протоколом на порту 443 (XRay), сайт должен отдать этот порт.
Положи в `/opt/skyblock-tracker` файл `docker-compose.override.yml` (в git его нет, автообновление его не трогает):

```yaml
services:
  caddy:
    ports: !override
      - "80:80"
```

и выполни `docker compose up -d`. Сайт останется на `http://IP` (без HTTPS: `set-domain.sh` в этом режиме не включай).
Протокол AmneziaWG работает по UDP на своём порту и сайту не мешает, тогда файл не нужен.

## Если что-то не так

- **Сайт не открывается по IP.** Проверь `docker compose ps`: у `app` должно быть `healthy`. Если нет, смотри `docker compose logs app`.
- **Нет сертификата.** Обычно домен ещё не указывает на сервер. `set-domain.sh` сам проверит это и подскажет. Журнал: `docker compose logs caddy`.
- **Обновление не приехало.** Смотри `docker compose logs updater`. Если там «возвращаю … и жду исправления», значит новая версия не собралась или не запустилась. Сайт остался на прошлой версии и обновится сам, когда в main появится исправление.
- **Письма с сервера не уходят.** Многие хостинги закрывают серверам почтовые порты 465/587. Попроси поддержку открыть их или впиши в `.env` ключ `RESEND_API_KEY` (resend.com, бесплатно): письма пойдут по HTTPS. Подробности — в `.env.example`. Слать письма прямо со своего сервера (без Gmail и Resend) — [docs/mail.md](docs/mail.md).
- **Пароль из `.env` не подходит.** Docker Compose понимает `$` в `.env` как подстановку. Если в пароле есть `$`, напиши его как `$$`.
