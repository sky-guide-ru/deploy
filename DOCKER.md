# Sky Guide на сервере: Docker, Caddy, автообновление, бэкапы

## Как устроено

На сервере одна папка — клон этого репо (по умолчанию `/opt/sky-guide`). В ней:

```
/opt/sky-guide/
  docker-compose.yml, Caddyfile, *.sh   ← из репо deploy
  src/api/   src/web/                   ← клоны репо api и web (в git deploy не попадают)
  .env                                  ← ключи и настройки (пример: .env.example)
  data/                                 ← данные сайта: JSON-файлы, отдельной базы нет
  packs/  db/icons/                     ← ресурс-паки и готовые иконки
```

| Контейнер | Что делает | Память |
|---|---|---|
| `api` | сервер сайта: `/api`, `/v1`, Swagger, вход, страницы с SEO. Наружу не открыт. Единственный видит `data/` | лимит 1,5 ГБ, куча Node 1 ГБ |
| `web` | при старте кладёт собранный сайт в общий том `web_dist` (новые `assets/` первыми, `index.html` последним; старые `assets/` живут ещё 2 дня для открытых вкладок) | 128 МБ |
| `caddy` | порты 80/443, HTTPS-сертификат. Файлы `/assets/*` отдаёт сам из тома с кэшем навсегда, всё остальное — в `api` | 256 МБ |
| `updater` | раз в минуту смотрит `main` репо deploy, api и web и пересобирает только изменившееся. Не собралось или не отвечает — возвращает прошлый коммит | 256 МБ |

Почему 1,5 ГБ и 1 ГБ: на VPS 4 ГБ остальное нужно системе, Caddy, updater и сборке новой версии рядом с работающим сайтом.
Потолок кучи Node ниже лимита контейнера, поэтому Node чистит память раньше, чем контейнер упрётся в лимит. Сборка образов
(`npm install`, Vite) идёт вне лимитов контейнеров.

Страницы сайта (`/`, `/en/…`, `/roadmap` и т. д.) отдаёт `api`, а не Caddy: он подставляет в `index.html` SEO, язык,
счётчик и настройки из `.env`. Новый `index.html` api подхватывает сам, без перезапуска.

## Какой сервер нужен

Ubuntu 22.04/24.04 или Debian 12, от 2 ГБ памяти (на 1 ГБ скрипт добавит подкачку), диск от 15 ГБ, доступ по SSH под root.

## Установка на чистый сервер

```bash
curl -fsSLO https://raw.githubusercontent.com/sky-guide-ru/deploy/main/setup-vps.sh
bash setup-vps.sh
```

Скрипт ставит Docker, включает файрвол (SSH, 80, 443), клонирует deploy в `/opt/sky-guide` и api, web в `src/`,
создаёт `.env` из примера, собирает и запускает сайт, ставит ночные копии. Репо открытые: ключи для чтения не нужны.
Повторный запуск безопасен.

Дальше:
1. Ключи и настройки: `nano /opt/sky-guide/.env` (всё описано в `.env.example`), затем `docker compose up -d`.
2. Данные: архивом с ПК — `bash import-data.sh /root/move.tgz`, из прежней папки на этом сервере — `bash copy-data.sh /старая/папка`.
3. HTTPS: `bash set-domain.sh sky-guide.ru,www.sky-guide.ru` (A-записи уже указывают на сервер). Без домена — `set-domain.sh sslip`.

Архив с ПК (PowerShell, из папки с данными сайта):

```powershell
tar -czf move.tgz --exclude=data/neu-repo.zip --exclude=data/icons .env data db/icons packs
scp move.tgz root@IP:/root/
```

## Переезд с прежней сборки (один контейнер) на эту

Прежний сайт и его папка всё это время не трогаются. Порядок:

**1. Тестовый запуск рядом с живым сайтом.** Порты 80/443 заняты прежним сайтом, поэтому тестовая копия работает на 8080,
без автообновления, без писем и без ИИ-ключа (не тратит дневной бюджет живого сайта):

```bash
curl -fsSLO https://raw.githubusercontent.com/sky-guide-ru/deploy/main/setup-vps.sh
TEST=1 bash setup-vps.sh
bash /opt/sky-guide/copy-data.sh /opt/skyblock-tracker --test
```

Открыть: `http://test.sky-guide.ru:8080` (A-запись `test` → IP сервера) или `http://IP:8080`. Вход работает и по http.
Проверить: вход под настоящим аккаунтом, графики цен за 30 дней, «Что делать», рынок, `/api/docs`. Браузерный прогон с ПК:
`E2E_URL=http://test.sky-guide.ru:8080 npm run e2e`. Пока работают обе копии, ключ Hypixel тратят обе — тест лучше не держать сутками.

**2. Переключение** — только после «да» владельца, в спокойное время:

```bash
bash /opt/sky-guide/switch.sh /opt/skyblock-tracker
```

Скрипт заранее собирает новую версию, сохраняет копию данных прежнего сайта в `/root/before-switch-*.tgz`, останавливает прежний
сайт (папка и данные остаются), копирует свежие `data/` и `.env`, поднимает новую версию на 80/443 с прежними доменами и проверяет
её. Простой — около минуты (Caddy заново получает сертификаты). Не ответила за 3 минуты — скрипт сам запускает прежний сайт обратно.

`DEPLOY_MERGERS` и `GITHUB_TOKEN` (см. «Автообновление») впиши в `/opt/sky-guide/.env` ещё на тестовом запуске: переключение их сохранит.

**3. Откат** в любой момент позже:

```bash
bash /opt/sky-guide/rollback.sh /opt/skyblock-tracker
```

Новая версия останавливается, её данные (новые входы, отзывы, история цен) копируются в прежнюю папку — формат файлов тот же,
прежние данные сохраняются архивом в `/root`. Прежняя папка удаляется только отдельным решением владельца, не раньше чем через неделю.

## Автообновление

Всё, что слито в `main` репо deploy, api или web, само появляется на сервере через 1–5 минут:

| Изменилось | Что делает updater | Готово, когда |
|---|---|---|
| api | пересобирает и перезапускает `api` | `/healthz` отвечает |
| web | пересобирает `web`, он кладёт сборку в том | api видит сборку |
| deploy | применяет compose и Caddyfile (Caddyfile сначала проверяется), потом пересоздаёт сам себя | `/healthz` отвечает |

Не собралось или не отвечает 2 минуты — коммит этого репо откатывается, сайт остаётся на прошлой версии, а этот коммит
больше не ставится, пока в `main` не появится следующий. Изменения только в `.md`, `docs/`, `test/`, `e2e/` ничего не перезапускают.
Журнал — `data/deploy-log.json` (панель «Сервер» владельца) и `docker compose logs updater`.

**Только одобренное.** Если в `.env` задан `DEPLOY_MERGERS` (логины GitHub через запятую), updater ставит коммит, только
если каждый новый коммит `main` — слияние PR, и слил его кто-то из списка. Иначе коммит пропускается и в журнал пишется почему.
Сливать в `main` через merge commit или squash, не rebase. Без `GITHUB_TOKEN` проверка укладывается в 60 запросов к GitHub в час;
токен (только чтение) снимает этот предел. GitHub не ответил — проверка повторится через минуту.

Выключить: `AUTO_UPDATE=0` в `.env`, затем `docker compose up -d updater`. Обновить вручную прямо сейчас:

```bash
cd /opt/sky-guide && git pull && git -C src/api pull && git -C src/web pull && docker compose up -d --build
```

## Резервные копии

Каждую ночь в 04:30 (время сервера) `backup.sh` сохраняет `data/` и `.env` в `/var/backups/sky-guide` и хранит 14 последних копий.
Кэш (база NEU, иконки, ответы Hypixel) не копируется: сайт скачает его заново. Архив проверяется после записи: битый не заменит
последнюю хорошую копию. В копию попадает всё из `data/`: аккаунты, `session-secret`, история цен, рейтинг, отзывы, ключи API (`api-keys.json`, только хеши).

Хостер копий не делает, поэтому раз в неделю забирай свежую себе:

```powershell
scp root@IP:/var/backups/sky-guide/latest.tgz .\backup-sky-guide.tgz
```

Вернуть: `bash import-data.sh /var/backups/sky-guide/latest.tgz` (серверные строки `.env` — порты, домен, автообновление — остаются).

## Каждый день

Команды — на сервере в `/opt/sky-guide`:

| Что | Команда |
|---|---|
| Состояние | `docker compose ps` |
| Журнал сайта | `docker compose logs api --tail 100 -f` |
| Журнал автообновления | `docker compose logs updater --tail 50` |
| Поменял `.env` — применить | `docker compose up -d` |
| Добавил паки в `packs/` | `docker compose restart api` |
| Сколько памяти ест | `docker stats --no-stream` |
| Свой Caddyfile проверить | `docker compose run --rm --no-deps caddy caddy validate --config /etc/caddy/Caddyfile` |

## Безопасность

- Сервер сам ставит всё из `main`, поэтому доступ к GitHub = доступ к серверу: двухфакторный вход на GitHub, слияние в `main`
  только через PR с одобрением, на сервере `DEPLOY_MERGERS`.
- `.env` никому не пересылать и не коммитить. Пароль или ключ с `$` пиши как `$$`.
- Вход на сервер по SSH-ключу, пароль root длинный.
- IP посетителей не пишется ни в журнал Caddy (поля вырезаны фильтром, журнала запросов нет), ни в журнал api.
- Cloudflare-прокси перед сайтом не ставить: из России такие сайты часто не открываются.

## VPN на том же сервере

Если AmneziaVPN занимает порт 443 (XRay), положи рядом `docker-compose.override.yml` (в git его нет, автообновление его не трогает):

```yaml
services:
  caddy:
    ports: !override
      - "80:80"
```

и выполни `docker compose up -d`. Сайт останется на `http://IP`. AmneziaWG работает по UDP на своём порту и сайту не мешает.

## Если что-то не так

- **Сайт не открывается.** `docker compose ps`: у `api` и `caddy` должно быть `Up`. Журнал — `docker compose logs api`.
- **Белая страница или «Сайт обновляется».** Проверь `docker compose logs web`: сборка должна была лечь в том («сборка скопирована»).
- **Нет сертификата.** Домен ещё не указывает на сервер: `set-domain.sh` проверит это сам. Журнал — `docker compose logs caddy`.
- **Обновление не приехало.** `docker compose logs updater`: «возвращаю … и жду исправления» — новая версия не собралась,
  «не ставлю — PR слил не тот» — сработал `DEPLOY_MERGERS`.
- **Письма не уходят.** Хостинг закрывает почтовые порты: впиши `RESEND_API_KEY` или настрой прямую отправку — [docs/mail.md](docs/mail.md).
